# Run the full backend on your computer

This option runs Resonance's server, database, private file storage, image
processing, and background workflow on **your computer**. It does not use the
original owner's APIs or Cloudflare resources and needs **no Cloudflare account**.
Your own OpenRouter/Firecrawl services still run online and can charge your
account. This is not an offline AI model installation.

For a comparison with your own Cloudflare deployment, see
[SETUP.md](SETUP.md#choose-how-to-use-resonance).

## 1. Install tools and download the files

Follow [SETUP.md: install and download](SETUP.md#run-the-local-demo) through
opening the terminal in your extracted project folder. Use **Node.js 24 LTS or
newer**, Deno 2 and Google Chrome. Python 3 is only needed for the separate
static sample demo, not this server. `node --version` should show `v24` or later;
update Node and reopen the terminal if it does not.

All needed runtime files are on GitHub: `local/`, `worker/`, `acquisition/`,
`agent-config/`, `vendor/`, assets, migrations, seed, lockfiles and the configuration
examples. You do not need private development skills, the maintainer's `.env`,
credentials, test accounts or a prebuilt `dist/` folder.

## 2. Add your own API keys and password

Create [your own OpenRouter key](https://openrouter.ai/settings/keys) with a credit
limit. It supplies the current extraction, vision, generation, review and grading
models listed in [SERVICES.md](SERVICES.md#ai-and-grading). A paid chat subscription
is not an API key. To process/capture website links, also create your own
[Firecrawl account](https://www.firecrawl.dev/) with Browser Sandbox API access.
Permitted file/text uploads do not need Firecrawl. Search keys are optional.

In the project folder, copy `local.env.example` to **`.env.local`**:

```sh
cp local.env.example .env.local
```

`cp` works in macOS/Linux Terminal and Windows PowerShell. In Windows Command
Prompt use `copy local.env.example .env.local` instead. Enable filename extensions
so the new file does not become `.env.local.txt`. Dotfiles may be hidden in
Finder; use **Command+Shift+.** to show them. On Windows, use **View → Show →
Hidden items** if needed.

Open `.env.local` in a plain-text editor. Replace the password placeholder with
a unique password of at least **16 characters**, such as one generated by your
password manager. Put your key between the quotes after `OPENROUTER_API_KEY=`.
Add your own `FIRECRAWL_API_KEY` for website processing. Leave unused optional
values empty. Save the file without changing its name or using rich text.

These keys belong only in your private file. Do not paste them into a terminal
command, app Settings, GitHub, screenshots or chat. Git ignores `.env.local`.
The server never obtains keys from the maintainer's deployment. You can start
without keys to inspect the app, but AI processing reports a missing-credential
error until your own valid key is configured.

## 3. Install, build and start

Run one command at a time in that same terminal:

```sh
npm ci
deno task build
deno task start:local
```

Wait for the server's ready message, then open
[http://127.0.0.1:8787](http://127.0.0.1:8787) in Google Chrome. Sign in with the
password you saved. Keep the terminal open. Stop with **Ctrl+C**; to start another
day, return to this folder and run `deno task start:local` again.

The first start automatically creates the local database, applies the included
SQL migrations, initializes private storage and credentials, loads the agent
configuration, and starts scheduled/background work. You do not need to create
D1, R2, Access, a separate acquisition server or Cloudflare keys. The computer
backend uses the same learning workflow as the Cloudflare application, with
local replacements for its storage, image and scheduling bindings.

The listener accepts connections only on this computer's loopback address.
Do not change it to `0.0.0.0`, forward a router port, or expose the password form
through an unencrypted public address. The phone path below supplies private
HTTPS without opening the server to the public Internet.

## 4. Try the entire learning pipeline

This test uses **your own API credits**. Start small:

1. In **Library → Upload a private document**, paste a short lesson you wrote.
   Confirm permission for storage/transformation/external AI processing, then
   choose **Upload and process**.
2. Watch the Library card until knowledge extraction and paired question
   generation complete. Processing continues while the browser is closed, as
   long as the server terminal and computer remain running.
3. Once at least five eligible published knowledge-and-quiz pairs are available,
   study a batch in **Feed**, choose **Mark batch studied**, then answer its paired
   quizzes in **Review**. Check feedback and **Progress**.
4. For a website, use the Library's URL workflow or your configured Discover
   provider. Choose material whose rights permit processing. Your Firecrawl key
   handles page browsing/capture; the bundled local acquisition service handles
   robots checks and approved media. No separate acquisition deployment is
   needed in computer mode. Follow any permission/upload prompt; private,
   paywalled, blocked or disallowed pages are not bypassed.
5. A website captured as a PDF retains the selected page and eligible original
   images for the normal material pipeline. YouTube search remains metadata-only;
   it does not download videos/captions. Podcast search does not install automatic
   speech transcription. Upload your own permitted transcript when needed.

A small lesson may produce fewer than five useful points. Add more original
material rather than expecting the service to invent enough points for a batch.
Model/provider failures have named errors and can require a retry. Exact/choice
answer checks work without semantic grading; non-exact answers can remain pending
if your grading service is unavailable.

## 5. Use the same backend on your phone

Your phone must connect to the computer's server, not the phone's `localhost`.
Use [Tailscale](https://tailscale.com/docs/install) for a private connection:

1. Install Tailscale on **both** the computer and phone and sign in to the same
   account that you control. Keep both connected. Do not use the maintainer's
   account or share an API key with Tailscale.
2. In your Tailscale admin console, enable MagicDNS and HTTPS certificates if
   they are not enabled. Choose a computer name that does not reveal private
   information: HTTPS certificate names enter public certificate logs, although
   the website remains private to your Tailscale network.
3. With Resonance running, open a **second terminal** on the computer and run:

   ```sh
   tailscale serve --bg http://127.0.0.1:8787
   ```

   Accept any HTTPS activation prompt after reviewing it. If `tailscale` is not
   found, reopen the terminal and follow your installer/platform's CLI setup;
   see [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve).
   On macOS, the installed app's CLI may be available as
   `/Applications/Tailscale.app/Contents/MacOS/Tailscale` instead of `tailscale`.
4. Copy the **HTTPS address printed by Serve**, for example
   `https://my-computer.example-tailnet.ts.net`. Do not use **Funnel**, which would
   publish the service outside the private network.
5. Stop Resonance with Ctrl+C. Edit `.env.local`, uncomment `LOCAL_ORIGIN` by
   removing the leading `#`, and replace its example with your **exact HTTPS
   origin without a trailing slash**. Restart with `deno task start:local`.
6. Open that HTTPS address in Google Chrome on your computer and on your Android
   phone. On iPhone use Safari for home-screen installation. Sign in with the
   same local app password. Both devices now use the computer's server records.
7. Follow [device installation](SETUP.md#install-on-your-devices) using this
   address. Local mode uses your password, not a Cloudflare email code.

[Tailscale's HTTPS instructions](https://tailscale.com/docs/how-to/set-up-https-certificates)
explain certificate and naming behavior. Review its current account/plan terms.
Keep the computer awake and the server running for phone access, processing and
scheduled notifications. Tailscale connectivity alone does not start Resonance.
An app icon is not an offline copy of the backend.

## Data, updates and recovery

Your data lives in **`.private/local/`** inside the project folder, including
`resonance.sqlite`, private `objects/`, credentials and workflow state. This is
real learner data. Do not delete it as a build/cache cleanup step, or publish it
to GitHub. Browser-only sample-demo records are separate from these server records.
Cloudflare deployments are separate too; this setup does not import someone
else's hosted account.

To back up, stop the server with Ctrl+C, then copy the **whole `.private/local/`
folder** and `.env.local` to private backup storage. Keep database files, any
SQLite sidecars, object files and credentials together. Do not copy only the
SQLite file while the server is running. To restore, stop the server and restore
the matching whole folder and config before starting. Keep the app version that
matches the backup. The Library export alone is not a full server backup.

For an update, back up first. Download the new code or sync your fork, preserving
`.env.local` and the **whole** `.private/local/` folder. Run `npm ci`,
`deno task build`, then `deno task start:local`. Pending migrations apply
without resetting your learning history. Never overwrite a private config with
an example or reinitialize an existing database.

After an interrupted run, restart the server and inspect Library. Completed
steps remain saved. Waiting workflows restore their saved wait/event state;
interrupted in-flight work uses the existing recovery/retry policy. A provider
may charge a request that finished remotely before interruption; restarting
cannot promise an exact-once external charge or refund. Do not repeatedly start
new extraction runs to troubleshoot a pending one.

The server signs you out after restart; sign in again with your password.
Change the password/API keys by editing `.env.local` while stopped, then restart.
For notifications, computer mode creates its own VAPID keys automatically; keep
its credentials file stable. Android Chrome enrollment remains per device.
See [notifications](SETUP.md#notifications) for testing and delivery limits.
Scheduled jobs run only while the computer server is running; an asleep computer
cannot send a reminder at the requested time.

## Common problems

| Problem | Fix |
| --- | --- |
| `node:sqlite`, TypeScript import or `--env-file` unavailable | Install Node.js 24 LTS or newer and reopen the terminal. |
| Password placeholder/startup error | Edit the copied `.env.local`, choose a unique 16+ character password, save, then retry. |
| `.env.local` cannot be found | Copy the example in the project root; check hidden files and `.txt` extensions. |
| Sharp/native image dependency fails | Use a supported current 64-bit OS/Node installation and normal `npm ci` with optional dependencies enabled; see [Sharp installation](https://sharp.pixelplumbing.com/install/). Do not remove image checks. |
| Port 8787 or data directory already in use | Stop the previous local server with Ctrl+C. Do not run two servers on the same data. |
| Phone says unrecognized host/origin | `LOCAL_ORIGIN` must equal the exact HTTPS address from your private Serve configuration; restart after editing it. |
| Phone cannot connect | Check both Tailscale connections, Serve status, computer sleep and the running server terminal. |
| No AI processing | Configure your own valid OpenRouter key/credits and required model access; use Firecrawl for website processing. |
| Website blocked or upload requested | Respect the named rights/robots/authentication restriction; supply permitted material instead. |
| Build fails | Stop before starting the server, keep the error and fix the tool/dependency problem. Do not copy a build from the maintainer's live service. |

For help, share the failed step and named error without private text, keys,
credentials, cookie values or database contents. No API key belongs in a support
screenshot.
